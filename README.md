# 商品検索案内（仮称）要件書

## 1. 概要

スーパーマーケットやホームセンターなど、企業が事前に登録した店舗内で、利用者が探している商品を検索し、AR（拡張現実）を使って現在地から商品陳列場所までを矢印でナビゲーションするWebアプリケーション。

在庫の有無はAIが判定し、在庫がある場合のみ案内を行う。在庫がない場合は「在庫がありません」と表示し、案内を行わない。

## 2. アプリ構成

本サービスは以下2種類のWebアプリケーションで構成する。

| アプリ | 利用者 | 主な機能 |
|---|---|---|
| 消費者用アプリ | 一般利用者（買い物客） | 商品検索、AR経路案内、検索ランキング閲覧 |
| 管理者用アプリ（企業用） | 店舗運営企業の担当者 | 消費者用アプリの全機能 ＋ 商品登録、店舗内装登録、ログイン／ログアウト／新規登録 |

## 3. 消費者用アプリ

### 3.1 画面構成・画面遷移

1. **店舗選択画面（初期画面）**
   - 利用可能な企業／チェーン（例：〇〇スーパー、〇〇ホームセンター）を一覧から選択する。
2. **支店選択画面**
   - 選択した企業に紐づく支店（例：〇〇店、△△店）を一覧から選択する。
   - 選択した支店がAR対応店舗かどうかをここで確定する。
3. **商品検索画面**
   - 支店を選択した後に商品名・キーワードで検索できる。
   - 画面上部にハンバーガーメニューを設置し、以下にアクセスできるようにする。
     - 検索ランキング（人気検索ワード・人気商品ランキングなど）
     - その他メニュー項目（今後拡張、例：お気に入り、履歴など）
4. **商品詳細・在庫確認**
   - 検索結果から目的の商品をタップすると、AIが当該店舗の在庫有無を判定する。
     - 在庫あり：AR案内画面へ遷移し、現在地から商品陳列場所までの矢印案内を表示する。
     - 在庫なし：「在庫がありません」と表示し、案内は行わずに終了する（AR画面へは遷移しない）。
5. **AR案内画面**
   - AR対応店舗への入店を検知すると、AR機能が自動的に有効化される（利用者が店舗内にいる間、商品タップ時にすぐ矢印案内を開始できる状態になる）。
   - スマートフォンのカメラ映像上に、現在地から商品陳列場所までのルートを矢印でオーバーレイ表示する。
   - 店舗外への退店を検知すると、「店舗外に出ました」という警告画面を表示し、AR機能を終了して通常の検索画面に戻る。

### 3.2 入店・退店検知（AR機能の自動起動・終了）

- **入店検知**：店舗入口に設置されたQRコードの読み取り、またはビーコン・屋内測位等の技術により、利用者がAR対応店舗内に入ったことを検知する。検知した時点でAR機能を自動的に有効化する（利用者の手動操作を必要としない）。
- **退店検知**：同様の手段（QRコード再読み取り、測位範囲からの離脱検知等）により、利用者が店舗外に出たことを検知する。検知した時点で「店舗外に出ました」という警告画面を表示し、AR機能を強制終了する。
- 警告画面表示後は、通常の商品検索画面（支店選択済みの状態）に戻る。

### 3.3 機能要件

- **店舗検索・選択機能**：企業→支店の順で選択し、対象店舗を絞り込む。
- **商品検索機能**：支店ごとに登録された商品情報からキーワード検索を行う。
- **検索ランキング機能**：人気の検索キーワードや商品をランキング表示する（ハンバーガーメニューからアクセス）。
- **AI在庫判定機能**：商品タップ時にAnthropic APIを介してAIが在庫有無を判定し、結果に応じて案内可否を分岐する。
- **AR経路案内機能**：AR Foundationを用いて、現在地から商品陳列場所までの経路を矢印でリアルタイム表示する。
- **AR自動起動機能**：AR対応店舗への入店を検知した時点で、AR案内機能を自動的に有効化する。
- **退店警告・AR終了機能**：店舗外への退店を検知した時点で「店舗外に出ました」という警告画面を表示し、AR機能を終了する（店舗外への持ち出し防止・誤作動防止）。
- **AR利用可否の制御**：AR機能は企業側が「AR対応店舗」として登録した店舗でのみ利用可能とし、未登録店舗では検索機能のみ提供する（入店検知そのものも、AR対応店舗としてビーコン・QRコード等が設置された店舗でのみ行われる）。

## 4. 管理者用アプリ（企業用）

消費者用アプリの全機能に加えて、以下の機能を持つ。

### 4.1 機能要件

- **アカウント機能**
  - 新規登録（企業アカウント作成）
  - ログイン／ログアウト
- **商品登録機能**
  - 店舗（支店）ごとに商品情報（商品名、カテゴリ、価格、陳列場所座標など）を登録・編集・削除できる。
- **店舗内装登録機能**
  - AIが商品の陳列場所を特定できるよう、店舗内のマップ・レイアウト情報（什器配置、通路、座標情報など）を登録する。
  - AR案内時の経路計算・矢印表示の基礎データとして利用する。
- **AR対応店舗の設定**
  - 支店ごとにAR機能を有効化／無効化できる（AR機能は企業が登録した店舗でのみ利用可能という要件に対応）。
- **QRコード管理**
  - AR終了用QRコードの発行・店舗への設置情報を管理する（詳細は今後検討）。

## 5. AI在庫案内フローの詳細

1. 利用者が商品検索結果から商品をタップする。
2. Anthropic APIを利用し、店舗の在庫データをもとにAIが在庫有無を判定する。
3. 在庫あり → AR案内画面へ遷移し、経路案内を開始する。
4. 在庫なし → 「在庫がありません」と表示し、案内を行わず処理を終了する。

### 9.2 ディレクトリ構成

```
server/   … Express API サーバー（Firestoreに接続）
web/      … React フロントエンド（消費者用・管理者用を統合、Vite）
```

### 9.3 起動方法

```bash
# バックエンド
cd server
cp .env.example .env   # FIREBASE_PROJECT_ID / FIREBASE_CLIENT_EMAIL / FIREBASE_PRIVATE_KEY、必要ならGEMINI_API_KEYを設定
npm install
npm run seed            # サンプルデータ投入（サンプルスーパー／駅前店(AR対応)・郊外店(AR未対応)、admin@example.com / password123）
npm start                # http://localhost:4000

# フロントエンド（別ターミナル）
cd web
npm install
npm run dev              # https://localhost:5173 （/api を :4000 にプロキシ）
```

カメラ（QRコード読み取り・AR）はブラウザの仕様上、HTTPSまたはlocalhost以外では動作しないため、開発サーバーは自己署名証明書によるHTTPSで起動する（初回アクセス時にブラウザの警告が出るが「詳細」から進んで問題ない）。スマートフォン実機で確認する場合は、PCと同じWi-Fiに接続したうえで `npm run dev` 実行時に表示される `Network:` のURL（例: `https://192.168.x.x:5173`）にアクセスする。

### 9.3.1 カメラが使えない場合

「カメラの利用が許可されていません」等のエラーが出る場合は、多くの場合ブラウザまたはOSのカメラ権限が原因。

- ブラウザのアドレスバー付近のカメラアイコンから、このサイトへのカメラ許可状態を確認する。
- Macの場合：システム設定 > プライバシーとセキュリティ > カメラ で、使用しているブラウザ（Chrome/Safari等）が許可されているか確認する。
- ノートPC内蔵カメラ（前面カメラのみ）でも動作するよう、背面カメラが無い場合は自動的に利用可能なカメラにフォールバックする。
- 上記を確認後、画面上の「再試行する」ボタンでカメラを再取得できる。

### 9.4 実装した機能と要件書との対応

- **店舗選択→支店選択→商品検索**（3.1の1〜3）：`web/src/pages/consumer/` 配下に実装。
- **AI在庫判定→在庫あり/なしの分岐**（3.1の4、5章）：商品タップで `POST /products/:id/check-stock` を呼び出し、Gemini（または未設定時はモック）が判定。在庫なしの場合はAR画面へ遷移しない。
- **入店QR→AR自動有効化／退店QR→「店舗外に出ました」警告**（3.2）：QRコードは管理画面で発行（`qrcode`ライブラリでPNG生成）し、消費者アプリはブラウザカメラ＋`qr-scanner`ライブラリでリアルタイム読み取りを行う。
- **AR経路案内**（3.1の5）：入店口を基準とした商品陳列位置の方位・距離をサーバー側で計算し、WebXRセッション開始時のカメラ向きを基準に矢印（3Dオブジェクト）を表示。歩行に伴う残り距離はXRの自己位置トラッキングでリアルタイム更新される。WebXR非対応環境では、端末コンパスに基づく簡易矢印表示（距離は目安の静的表示）にフォールバックする。
- **ハンバーガーメニュー・検索ランキング**（3.3）：検索キーワード・商品タップを`search_logs`に記録し、直近30日の集計をランキング表示。
- **管理者アプリ**（4章）：新規登録／ログイン／ログアウト、商品CRUD、店舗内装登録（後述の「AR実測登録」）、入店・退店QRコードの発行画面を実装。

### 9.4.1 店舗内装登録＝AR実測登録（マップクリック方式から変更）

当初はマップ画像をクリックして入店口・商品の位置を指定する方式だったが、実店舗の実寸を反映できないため、**WebXRのカメラを見ながら実際に店内を歩いてその場でタップして登録する方式**に変更した（`web/src/components/ar/ArAdminCapture.jsx`）。

1. 管理者アプリの「店舗内装・AR設定」で「AR登録を開始する」を押すとARカメラ映像が起動する。
2. 入店口に立って「①入店口としてここを登録」をタップ → その瞬間のカメラの位置・向きが方位0°の基準になる。
3. 各商品の実際の陳列場所まで歩いて、商品一覧から「ここに登録」をタップ → 基準からの方位（bearingDeg）・水平距離（distanceM）をその場で算出し、商品データに直接保存する（`PUT /admin/products/:id/position`）。
4. 「AR登録を終了」を押すと、店舗のAR案内が自動的に有効になる。

これにより、消費者向けAR案内（3.1の5）で使う方位・距離は、マップ上の仮想座標ではなく実際に計測した値になる。WebXR非対応端末（PCなど）ではこの登録機能自体が使えない旨のメッセージを表示する（実店舗を歩く必要がある性質上、対応スマートフォンでの操作を前提とする）。

### 9.4.2 管理者ログインをFirebase Authenticationに変更

当初は自前でJWT発行＋bcryptによるパスワードハッシュを実装していたが、ユーザーの希望により**Firebase Authentication**（既存のFirebaseプロジェクト`syouhinnkennsakuannnai`）に置き換えた。

- **新規登録**：`POST /api/auth/register` がサーバー側でFirebase Admin SDKの`auth.createUser()`を呼び、Firebase Authenticationにユーザーを作成する。同時にFirestoreへ企業（`companies`）・ユーザー付随情報（`users/{uid}`、companyIdのみ）を保存する。レスポンスにカスタムトークンを含め、フロントは`signInWithCustomToken()`でログイン状態にする。
- **ログイン**：パスワードの検証はFirebase側でしかできないため、フロントエンドがFirebase Client SDKの`signInWithEmailAndPassword()`を直接呼び出す（バックエンドを経由しない）。取得したIDトークンを以降のAPIリクエストの`Authorization: Bearer`ヘッダーに使う。
- **サーバー側の認証**：`server/src/middleware/requireAuth.js`が`auth.verifyIdToken()`でIDトークンを検証し、Firestoreの`users/{uid}`からcompanyIdを取得する。
- **セッション永続化**：Firebase Client SDKが認証状態をブラウザに保持するため、ページ再読み込み後も自動的に復元される（`onIdTokenChanged`で監視）。

デプロイ時のハマりどころ：`firebase-admin`が内部で使う`jwks-rsa@4.x`は`jose@6`（ESM専用）に依存しており、Vercelの関数実行環境で`ERR_REQUIRE_ESM`エラーが発生した。`package.json`の`overrides`で`jwks-rsa`を`3.2.2`（CommonJS対応の`jose@4`系を使う最終バージョン）に固定して解消した。

### 9.5 プロトタイプ段階での簡略化・既知の制約

- **屋内測位（歩行中の自己位置）は未実装**：AR案内中の残り距離はWebXRの自己位置トラッキングでリアルタイム更新されるが、通路や什器を避けた経路探索（ルーティング）はしておらず、常に直線距離・直線方位で案内する。
- **AR登録・AR案内どちらも「その場での向き」が基準**：管理者が入店口登録した瞬間の向きと、消費者が入店時に較正する向きが実運用ではズレる可能性がある（どちらも「入店時に店の奥を向く」という前提に依存する簡易実装）。
- **QRコードの実運用設計は未検討**：入店口・出口それぞれのQR画像は管理画面から発行できるが、実店舗での印刷・掲示運用、誤スキャン対策（8章）は別途検討が必要。
- **WebXR (`immersive-ar`) は対応端末が限られる**（主にAndroid Chrome等）。消費者向けAR案内はiPhone/Safariなど非対応環境ではカメラ＋コンパスによる簡易AR表示に自動フォールバックするが、管理者向けのAR実測登録機能はWebXR対応端末が必須。
- **開発サーバーは自己署名証明書によるHTTPS**：本番運用時は正式な証明書での配信が必須（自己署名証明書はブラウザ警告が出るため、開発・検証用途に限る）。

## 10. デプロイ（Vercel）

localhost以外からも（スマートフォン実機を含め）動作確認できるよう、Vercelにデプロイしている。

- **公開URL**：https://syouhinnkennsakuannnai.vercel.app
- Vercelの正式なHTTPS証明書で配信されるため、自己署名証明書の警告なしにスマートフォン実機からもAR・カメラ機能を確認できる。

### 10.1 デプロイ構成

- フロントエンド（`web/`のビルド成果物）は静的ファイルとして配信。
- バックエンド（`server/`のExpressアプリ）は1つのVercel Serverless Function（`api/index.js`）にまとめ、`vercel.json`のrewritesで`/api/:path*`を丸ごとこの関数に転送している。
- ルーティング：`vercel.json`で `/api/*` → APIファンクション、それ以外 → `index.html`（React Routerによるクライアント側ルーティングのため）。

### 10.2 データ永続化

当初はSQLite（better-sqlite3）をVercel Serverless Functionsの一時領域（`/tmp`）に置いていたが、**`/tmp`はインスタンスごと・コールドスタートごとに独立してリセットされるため、新規登録や支店追加などの書き込みが別インスタンスから見えなくなる**という不具合が発生した（ログイン失敗、支店一覧の表示欠落など）。これを解消するため一度Postgres（Neon）に移行し、その後ユーザーの希望により**Firestore（Firebase、既存プロジェクト`syouhinnkennsakuannnai`）に移行した**（`server/src/db.js`）。ローカル開発・Vercel本番のどちらも同じFirestoreを共有するため、管理者アプリでの新規登録・支店追加・商品登録・AR実測登録は、環境やインスタンスを問わず常に正しく永続化される。

- FirestoreはNoSQLドキュメントDBのため、SQLのJOINに相当する処理（検索ランキング集計など）はアプリケーション側で行っている（`server/src/routes/ranking.js`）。
- Firestoreは「等価条件＋別フィールドの範囲条件・並び替え」の組み合わせに複合インデックスの作成が必要になる場合があるため、本実装ではあえて単純な等価フィルタのみでまとめて取得し、絞り込み・集計・並び替えはすべてアプリ側（Node.js）で行う設計にして、複合インデックス作成（Firebaseコンソールでの手動操作が必要）を一切不要にしている。
- 認証情報はFirebase Admin SDKのサービスアカウント鍵から`FIREBASE_PROJECT_ID`・`FIREBASE_CLIENT_EMAIL`・`FIREBASE_PRIVATE_KEY`の3つの環境変数を抽出して使用（サービスアカウントのJSONファイル自体はコミットしない。`.gitignore`参照）。

### 10.3 環境変数

Vercelプロジェクトに以下を設定済み／設定可能：

- `FIREBASE_PROJECT_ID` / `FIREBASE_CLIENT_EMAIL` / `FIREBASE_PRIVATE_KEY`：Firebase Admin SDKのサービスアカウント鍵から設定済み（サーバー側の認証・Firestoreアクセス用）。
- `GEMINI_API_KEY`：未設定（在庫判定はモックロジックで動作）。実際にGemini APIで判定したい場合は、Vercelダッシュボードまたは`vercel env add GEMINI_API_KEY`でキーを追加後、再デプロイする。

なお、フロントエンド（`web/src/firebase.js`）にはFirebaseの**ウェブアプリ設定**（apiKey等）をハードコードしている。これはFirebase Authenticationの許可済みドメイン設定やFirestoreセキュリティルールで保護される前提の公開情報であり、秘密鍵（サービスアカウント）とは異なり環境変数化やコミット除外の必要はない。
